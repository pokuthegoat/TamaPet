1. WHAT THIS PROJECT IS
================================================================

"Crypto tek" — a website built specifically to get tokenised. The premise:
the better the narrative/story the site tells, the more people trade the
token built around it. This site is the narrative layer for a Tamagotchi-
style pet game called TamaPad.

CORE CONCEPT:
- User adopts a virtual pet (picks an animal).
- Raises it by interacting with it: feeding, bathing, minigames — all give XP.
- In-game currency is earned by completing quests (milestones with your pet).
- Currency buys clothes/items for the pet (exact details still TBD).
- Possible later features: spin the wheel, daily rewards.

THE HOOK (this is the whole point of the project):
- You can tokenise your pet — launch a coin for it via pump.fun.
- One pet = one coin. NOT one site-wide coin. Every owner launches their
  own coin for their own pet. Tokenomics are per-pet, not platform-wide.
- Trading fees from that coin go to a charity the pet's owner (the
  launcher) picks. Funds sit in escrow (mechanism not yet designed).
- Marketing angle / tagline logic: "every level you progress with your
  pet, a real one is saved in real life."

BUILD ORDER:
1. Landing / marketing page first (this is what's been built so far).
2. The actual game later. Nothing game-related has been built yet —
   only the marketing landing page.

their exact orange/black palette, pixel-dither illustrations, Space

CURRENT STATE (per explicit user instruction): ALL of that design was
scrapped. The user said: "scrap every single piece of design so the only
thing that is left is the layout and text, for images and illustrations
use placeholders." This was executed literally:
- System font stack only (no custom fonts).
- Black / white / grey only. No color palette.
- Plain 1px bordered buttons, no rounded pills, no shadows, no
  decorative effects.
- Every image/illustration/icon slot = a plain dashed-border grey box
  reading "[ IMAGE PLACEHOLDER ]" (or "[ ICON ]" for the small ones).
- Layout (grid/flex structure, spacing, section order, responsive
  breakpoints) was KEPT — that part was fine, only the decoration was
  wrong.

DO NOT reintroduce colors, custom fonts, or an illustration style
without new, explicit direction from the user. The visual identity is
currently an open question and should stay minimal/placeholder until

6. THE HERO SECTION — CURRENT STATE (the only section with real visual
   treatment beyond plain placeholders)
================================================================

The hero went through several iterations in one session:

a) Originally: centered text, plain grey placeholder box below it for
   where a pet illustration would go.

b) User asked for layout thinking: recommended either a centered-stack
   layout or a full-bleed cinematic treatment. User picked full-bleed.

c) User supplied a real image (not AI-generated by me — I don't have
   image-gen tools in this environment) via a local file path and said
   "use this image for the hero." It's a cyanotype-style (deep blue,
   etching/engraving look) landscape photo/illustration — NOT a pet
   image. Deliberately atmospheric/moody, not literal. Saved to
   D:\TamaPad\assets\hero.png. This image was swapped once already
   (mountain range → valley with a winding river) using the same
   filename/path — if the user gives another image, just overwrite
   assets/hero.png the same way (cp to that exact path), and be aware
   the browser aggressively caches images by URL — a page-level
   cache-busting query string is NOT enough; you need a hard reload
   (ctrl+shift+r) when verifying the swap in-browser.

d) Full-bleed treatment built: background-image covers the whole hero
   section (min-height:92vh), with a dark linear-gradient overlay on
   top for text legibility, white text.

e) User said "now make it cinematic." I interpreted this as motion —
   added a Ken Burns slow-zoom animation on the background, letterbox
   bars (black bars top/bottom like widescreen film), and staggered
   fade-up entrance animations on the text. User said "revert"
   immediately. IMPORTANT LESSON: when THIS user says "cinematic," they
   mean layout/composition, NOT animation or motion effects. Don't
   default to adding motion for this kind of request again.

f) User then clarified directly: "when i said 'make it cinematic' i
   wanted you to change the LAYOUT of the hero, to make it look
   better." I proposed three options: (1) lower-third/bottom-left text
   placement like a movie poster, (2) static letterbox bars, (3) both
   combined. User said "dont do 2" — so only #1 was built.

CURRENT HERO LAYOUT (as it stands now):
- Full-bleed background image (assets/hero.png), min-height:92vh.
- Text block (eyebrow "01 / ADOPT", headline "Raise a pet. Save a life.",
  subtext, two buttons) is anchored BOTTOM-LEFT, not centered.
- Gradient overlay is weighted toward the bottom (darker near the text,
  lighter near the top) so the image breathes at the top and text stays
  legible at the bottom — classic movie-poster composition.
- NO letterbox bars. NO animation/motion of any kind. This was explicit.
- Verified working on both desktop and mobile (390px width) before
  being called done.

Do not reintroduce letterbox bars or motion/animation on the hero
without new explicit direction — both were explicitly rejected.
